2.3 RBAC: authentication vs authorization
============================================================
# IMPORTANT: 'kubectl --token=X' alone is NOT a valid test on this cluster --
# the ambient admin kubeconfig also carries a client CERTIFICATE, and mutual-TLS
# client-cert auth wins over a bearer token, so every call would silently run as
# admin regardless of which token is passed (verified: try it, everything says
# 'yes' to auth can-i --list). A clean, TOKEN-ONLY kubeconfig avoids that, exactly
# like Assignment 1's bonus RBAC evidence (evidence/bonus-rbac.txt) already did.
# backend-sa: has an identity (mounted token) but NO Role/RoleBinding targets it
